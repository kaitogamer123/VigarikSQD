# ТЗ: «Поиск команды» (биржа игроков LFT)

**Проект:** Telegram-бот ViGarik Squad
**Модуль:** `league/` (составы) + уведомления
**Версия:** 1.1 от 13.11.2026
**Статус:** согласовано с заказчиком (Олег), можно приступать
**Исполнитель:** агент, работающий по этому документу

---

## 1. Зачем это нужно

Игроки хотят играть турниры и скримы, но не могут найти команду: у них нет состава, а лидеры существующих составов не знают, кто свободен. Сейчас единственный путь — писать в чат или подавать заявки вслепую.

Решение: биржа игроков.
- Игрок без состава включает статус «Ищу команду» и попадает в общий список (анкета).
- Лидер/заместитель состава открывает список, смотрит анкету и приглашает игрока в свой состав.
- Игрок получает приглашение в личку вместе с анкетой команды и принимает/отклоняет.
- После принятия и лидеру, и игроку приходят теги друг друга для связи.
- Анкета живёт 7 дней, затем скрывается автоматически с уведомлением игроку.

## 2. Согласованные решения (менять без согласования нельзя)

1. Список ищущих видят **все** зарегистрированные участники.
2. Отдельный выбор режима (1v1/2v2/3v3) **не делаем**. Вместо него — необязательный комментарий, игрок сам пишет «только турниры», «запасной игрок» и т.п.
3. Комментарий в анкете — **есть, необязательный**, до 200 символов.
4. Анкета висит **7 дней** автоматически; при скрытии игроку приходит **уведомление**.
5. `@username` нигде **не показываем** (игроки могут блокать друг друга). Контакт — только обмен тегами после принятия приглашения.
6. Уведомления лидерам о новых анкетах — с **переключателем вкл/выкл**.
7. В приглашении игрок должен видеть **анкету команды** (та же карточка, что в «🌍 Все составы»).
8. После принятия приглашения **обмен тегами**: обоим в личку приходят теги друг друга.

## 3. Роли и права

| Действие | Игрок без состава | Участник состава | Лидер / зам с `can_invite` |
|---|---|---|---|
| Включить/выключить поиск | ✅ | ❌ | ❌ |
| Видеть список ищущих | ✅ | ✅ | ✅ |
| Открыть анкету игрока | ✅ | ✅ | ✅ |
| Пригласить в состав | ❌ | ❌ | ✅ |
| Отозвать своё приглашение | — | — | ✅ |

Правила:
- статус поиска доступен только зарегистрированным (`members.registered = 1`);
- игрок в составе не может быть в поиске; при вступлении в состав статус снимается автоматически;
- приглашать может только лидер или заместитель с правом `can_invite` и только при наличии свободного слота;
- приглашение самому себе невозможно (игрок без состава не имеет права приглашать).

## 4. Пользовательские сценарии

### UC-1. Игрок включает поиск
1. «Составы» → кнопка **«🔎 Я ищу команду»**.
2. Бот создаёт анкету (ник, тег, кубки, клан — из базы) и показывает карточку статуса.
3. Ответ: «✅ Ты в поиске. Лидеры составов увидят тебя в списке».

### UC-2. Игрок выключает поиск
1. В карточке статуса **«⏹ Остановить поиск»**.
2. Анкета скрывается из списка. Повторное включение доступно сразу (кулдаун 60 сек).

### UC-3. Игрок меняет комментарий
1. В карточке статуса **«✏️ Комментарий»** → ввод текста (FSM, кнопки «◀️ Назад» / «❌ Отмена»).
2. Пустой ввод = удалить комментарий. Лимит 200 символов.

### UC-4. Игрок продлевает анкету
1. В карточке статуса **«🔁 Продлить на 7 дней»**.
2. `expires_at` = now + 7 дней, `updated_at` обновляется.

### UC-5. Просмотр списка
1. «Составы» → **«🔎 Игроки в поиске»**.
2. Постраничный список по 10 записей, сортировка по свежести (`updated_at DESC`).
3. Нажатие на игрока → анкета игрока.

### UC-6. Лидер приглашает
1. В анкете игрока **«📨 Пригласить в состав»** (видна только тем, кто имеет право и имеет состав).
2. Бот проверяет: права, свободный слот, игрок не в составе, не приглашён этим составом ранее.
3. Игроку в личку: приглашение + **анкета команды** (название, тег, верификация/MMR, состав по слотам, свободные места — как в «🌍 Все составы») + кнопки «✅ Принять» / «❌ Отклонить».
4. Лидеру: «✅ Приглашение отправлено». При закрытых личках у игрока: «⚠️ У игрока закрыты личные сообщения. Приглашение сохранено — он увидит его в списке приглашений».

### UC-7. Игрок принимает
1. «✅ Принять» (из лички или из «📥 Приглашения в состав»).
2. Игрок занимает свободный слот (`_fill_slot`), остальные его приглашения и заявки удаляются.
3. Статус поиска снимается автоматически.
4. Обмен тегами:
   - игроку: «✅ Ты вступил в состав {name} [{tag}]. Тег лидера: {лидер player_tag} ({лидер game_nick})»;
   - лидеру: «✅ {nick} вступил в твой состав. Его тег: {player_tag}».

### UC-8. Игрок отклоняет
1. «❌ Отклонить» → приглашение удаляется, игрок остаётся в поиске.
2. Лидеру ничего не отправляем (не провоцировать конфликт).

### UC-9. Истечение 7 дней
1. Watchdog находит истёкшие анкеты, ставит `is_active = 0`.
2. Каждому владельцу: «⏳ Твоя анкета в поиске команды скрыта. Разместить ещё на 7 дней?» + кнопка «🔁 Разместить ещё на 7 дней».

### UC-10. Уведомления лидерам (тумблер)
1. В «⚙️ Настройка состава» появляется кнопка **«🔔 Уведомления о поиске: Вкл/Выкл»**.
2. По умолчанию — **вкл**.
3. Когда игрок включает поиск, всем лидерам составов (у которых тумблер вкл **и** есть свободный слот) приходит уведомление: краткая анкета + кнопки «📨 Пригласить» и «👁 Открыть анкету».
4. Заместителей не уведомляем (v1).

### UC-11. Игрок уже в составе
Кнопки поиска нет. Если игрок вступил в состав, пока был в поиске, — статус снимается автоматически.

## 5. Анкета игрока (текст сообщения)

```
🔎 Игрок в поиске

👤 Ник: PlayerOne
🏷 Тег: #ABC123
🏆 Кубки: 45 320
🏰 Клан: ViGarik Squad
📅 В поиске с: 12.11.2026
⏳ Скрытие: 19.11.2026
💬 «Только турниры»
```

- Своя карточка: «⏹ Остановить поиск», «✏️ Комментарий», «🔁 Продлить на 7 дней», «◀️ Назад».
- Чужая карточка (для всех): те же данные; кнопка «📨 Пригласить в состав» только у лидера/зама с `can_invite`.
- Если `player_tag` пуст — показывать «—». Клан брать из `members.clan`, отображать через `config.CLAN_DISPLAY`/`CLAN_HEADER_EMOJI` по ключу; неизвестный клан — как есть.
- Кубки/ник подтягиваются из `members` в момент показа (не кэшируются в анкете).

## 6. Функциональные требования

- FR-1. Одна активная анкета на пользователя (ключ `user_id`).
- FR-2. Список показывает только `is_active = 1 AND expires_at > now`.
- FR-3. Сортировка по `updated_at DESC`, пагинация по 10.
- FR-4. Пустое состояние: «📭 Сейчас никто не ищет команду».
- FR-5. Автоснятие статуса: вступление в состав (принятие приглашения или заявки), выход из клана (`members.clan` пуст), истечение 7 дней.
- FR-6. Истёкшие записи не удаляются физически (статистика), но не показываются.
- FR-7. Повторное приглашение не создаёт дубль (уникальный индекс `league_invites (league_id, invitee_id)` уже есть).
- FR-8. Антифлуд: переключение статуса не чаще 1 раза в 60 секунд (по образцу `utils/push_limiter.py`).
- FR-9. Все пользовательские тексты экранируются `hd.quote`; все вызовы Telegram API — в `try/except`, ошибки не роняют хендлеры.
- FR-10. В публичных местах нет Telegram ID и `@username`.
- FR-11. Ошибки логируются в `logging` с контекстом (`user_id`, `league_id`).

## 7. Модель данных

### 7.1. Новая таблица (в `league/league_db.py`, функция `init_league_db`)

```sql
CREATE TABLE IF NOT EXISTS lft_searches (
    user_id     INTEGER PRIMARY KEY,
    comment     TEXT DEFAULT '',
    is_active   INTEGER DEFAULT 1,
    created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
    expires_at  DATETIME NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_lft_active
    ON lft_searches (is_active, expires_at, updated_at);
```

Поле `formats` не заводить (решение 2) — достаточно `comment`.

### 7.2. Тумблер уведомлений лидера

Добавить колонку в `leagues` (миграция через `PRAGMA table_info`):
```sql
ALTER TABLE leagues ADD COLUMN notify_lft INTEGER DEFAULT 1
```

### 7.3. CRUD-функции (туда же, в `league_db.py`)

```python
lft_set_active(user_id: int, active: bool, days: int = 7) -> bool
lft_get(user_id: int) -> Row | None
lft_list(page: int, per_page: int = 10) -> list[Row]   # JOIN members, только активные
lft_count() -> int
lft_touch(user_id: int) -> None        # обновить updated_at/expires_at
lft_set_comment(user_id: int, comment: str) -> None
lft_disable(user_id: int) -> None
lft_expire_stale(bot) -> int           # watchdog: скрыть истёкшие + уведомить владельцев
```

`lft_list` джойнит `lft_searches` с `vigarik.db → members` (ник, тег, кубки, клан).

## 8. Интерфейс и callback-схема

### 8.1. Кнопки в корневом меню «Составы» (`league/ui.py::_root_keyboard`)

Игрок без состава:
```
🌍 Все составы
📝 Подать заявку в состав
📩 Мои заявки | 📥 Приглашения в состав
➕ Создать состав
🔎 Я ищу команду          ← новая (не показывать, если анкета активна; вместо неё «⏹ Остановить поиск»)
👀 Игроки в поиске         ← новая
◀️ Назад в главное меню
```

Лидер:
```
🌍 Все составы | 🏆 Лиги / 🛡 Верифицировать состав
⚙️ Настройка состава
📋 Заявки в состав
🔎 Игроки в поиске         ← новая
📜 История матчей
◀️ Назад в главное меню
```

Заместитель — как у лидера, но без строки «📋 Заявки в состав» при отсутствии права.
В «⚙️ Настройка состава» (`_settings_keyboard`) добавить строку: `🔔 Уведомления о поиске: Вкл` / `Выкл` — только лидеру.

### 8.2. Callback data

| Callback | Действие |
|---|---|
| `lft:toggle` | вкл/выкл поиск |
| `lft:status` | своя карточка |
| `lft:comment` | FSM ввода комментария |
| `lft:extend` | продлить на 7 дней |
| `lft:list:{page}` | список, страница |
| `lft:card:{user_id}` | анкета игрока |
| `lft:invite:{user_id}` | пригласить |
| `lft:notify_toggle` | тумблер уведомлений (лидер) |

Все callback ≤ 64 байт.

## 10. Критерии приёмки

1. Игрок без состава включает поиск и появляется в списке; кнопка меняется на «⏹ Остановить поиск».
2. Остановка убирает из списка.
3. Игрок в составе не может включить поиск.
4. Список видят все; пагинация и сортировка по свежести работают.
5. Анкета игрока показывает актуальные ник/тег/кубки/клан и комментарий.
6. Лидер со свободным слотом отправляет приглашение; игрок получает ЛС с анкетой команды и кнопками.
7. Принятие: слот занят, поиск снят, остальные приглашения/заявки удалены, теги пришли обоим сторонам.
8. При полном составе приглашение не уходит, ошибка понятная (alert).
9. Повторное приглашение не создаёт дубль.
10. Через 7 дней анкета скрыта, владельцу пришло уведомление, «🔁 Разместить ещё на 7 дней» работает.
11. Тумблер вкл → уведомления приходят только лидерам со свободными слотами; выкл → не приходят.
12. Обычный участник не видит кнопку «Пригласить».
13. Существующие заявки/приглашения/скримы работают как раньше (регресс).
14. Закрытые лички и удалённые сообщения не ломают бота.

## 11. План на 3 дня

**День 1 — база и личный статус.** Таблица `lft_searches`, колонка `notify_lft`, CRUD, константы `config.py`, кнопки меню, toggle, своя карточка, FSM комментария, кулдаун. К вечеру: рабочий личный статус + карточка.

**День 2 — биржа и приглашения.** Список с пагинацией, анкета игрока, приглашение с анкетой команды (переиспользование карточки состава), принятие/отказ, обмен тегами, автоснятие при вступлении. К вечеру: полный цикл «нашёл → пригласил → вступил».

**День 3 — автоматика и стабильность.** `lft_expire_stale` + уведомление об истечении + продление, тумблер уведомлений, краевые случаи (игрок вышел из клана, устаревшие callback, пустые состояния), регресс составов/заявок/приглашений, деплой и живой тест.

Оценка: ~21 час суммарно.

## 12. Не входит в первую версию

- автоподбор команды по алгоритму/рейтингу;
- привязка поиска к конкретному турниру;
- чат/переговоры внутри бота;
- рейтинги, отзывы, фильтры по клану/кубкам/формату;
- лимит приглашений в час;
- уведомление лидеров, чей игрок принял приглашение другого состава («ушёл к другому»);
- предложение вернуться в поиск после кика/выхода из состава.

## 13. Примечания для исполнителя

- Проверять всё на тестовом турнире/составе, боевые данные `league.db` и `vigarik.db` не трогать миграциями с потерей данных — только `ADD COLUMN` и `CREATE TABLE IF NOT EXISTS`.
- `init_league_db()` вызывается при импорте `league/handlers.py` — новые таблицы создавать там же, чтобы миграция шла автоматически на проде.
- Не блокировать event loop: SQLite-вызовы синхронные, как и во всём существующем коде — допустимо, но держать запросы простыми и быстрыми.
- Кнопка «Я ищу команду» у игрока с активной анкетой не показывается вообще (вместо неё «⏹ Остановить поиск») — чтобы не плодить дубли состояний.
- При отключении уведомлений (тумблер) состояние хранится в `leagues.notify_lft`, переключение мгновенное, без подтверждений.
